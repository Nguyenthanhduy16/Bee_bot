## Proposed independent Sheets acceptance cases

These target the existing `JsonSchedule` contract (`list_people`, `list_assignments`, `get_assignment`, `apply_updates(updates, expected)`, `next_write_fault`) and service reconciliation. They run against a synthetic Sheets **test copy** only, through whatever adapter the accepted Core design provides. Implementation follows the Lead-accepted design.

1. **Read mapping:** a fixture with merged B/C/F/G cells and date-block headers in A yields assignments with correct date + Sáng 09:00–13:00 / Chiều 14:00–18:00 (Asia/Ho_Chi_Minh). An empty D is never filled from the previous row; K–P conflicts are reported but B–J wins.
2. **Stable identity:** inserting or sorting rows above a target does not change `assignment_id`/`shift_id`; STT and row number are never the key. A duplicate or unknown name in D is surfaced to ops, not guessed.
3. **Write D only:** a replacement changes exactly the one D cell; J, E, F, notes and every other cell are byte-identical (diff the whole range before/after); `revision` increments.
4. **J-change tolerance:** an ops edit to J between read and write does not block the write and is not overwritten (the snapshot signature ignores J).
5. **D-conflict stop:** an ops edit to the target D (or to the recipient's overlapping D) between snapshot and write produces `SCHEDULE_CHANGED`, no write, and an ops alert.
6. **Read–write race (known limit, Q4):** an ops edit after the adapter's pre-write read but before the write. Record whether the post-write read detects it; document the result as a limitation, not a lock.
7. **Swap atomicity:** a swap writes both D cells and reads both back. Inject a `partial` fault (first write only) → `WRITE_UNCERTAIN`, the reservation is kept, no automatic rollback or retry; `reconcile_request` completes only when both match.
8. **Timeouts:** `timeout_before` (no change) and `timeout_after` (change applied) both lead to `WRITE_UNCERTAIN`. Reconciliation distinguishes them by reading actual values, with no blind repeat.
9. **Clear failure:** `WRITE_FAILED` leaves the request awaiting ops/reserved; no reassignment to the next responder.
10. **Restart recovery:** kill the process between the write and the status update; after restart, maintenance reconciles once and does not write again.
11. **Concurrency:** two recipients accept the same position at the same moment → exactly one D write; the loser gets an authoritative "position taken" result.
12. **Quota/HTTP errors:** 429/5xx on read is retried safely or surfaced; 429/5xx on write is treated as uncertain, never as success. The credential is read from outside Git, and logs contain no cell values or IDs.
13. **Scope guard:** the adapter refuses any spreadsheet/tab not on the configured test-copy allowlist (the production ID is rejected), and the model has no arbitrary cell-write tool.

### S1 — High (PROVEN): populated rows with blank/text STT are silently out of scope → missed overlap, double booking completes

- Where: `sheets_adapter.py:101-102` (`if not _numeric_row(a): continue`) and `:156-162` (`writable` only considers emitted diagnostics).
- Reproducer: `test_GAP_row_with_coach_but_unrecognised_stt_is_silently_out_of_scope[None|'3'|'x']`. Row 11 has valid B–G and a roster name (Synthetic Binh, day-2 Sáng), but A is blank, the text `'3'`, or `'x'`. The row disappears with `diagnostics == []`, `writable is True`, and the replacement of Chi's day-2 Sáng row 9 to Binh **completes**, leaving Binh in two overlapping positions.
- Control: `test_control_numeric_stt_row_blocks_the_same_double_booking` shows the same data with a numeric STT gives `needs_ops / SCHEDULE_CONFLICT` and no write.
